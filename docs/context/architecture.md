# Architecture

Static Vite application using strict TypeScript and Three.js. `index.html` loads `src/main.ts`, which manages language state, document metadata, page rendering, and language/email interactions. Bilingual copy and project records live in `src/content.ts`; semantic page sections are assembled by reusable render functions in `src/views.ts`. Language changes rebuild the page and dispose of the previous scene. Local storage persistence is guarded, so language switching remains available for the current session when storage is unavailable.

`src/scene.ts` is a separate dynamically loaded Three.js chunk. Its fragment shader samples the optimized space photograph, displacing photographed plasma and adding moving copper highlights around the accretion disk and event horizon. Star luminance varies gently and pointer movement adds eased parallax. Shader coordinates use the source image dimensions and the CSS background size and position, preserving alignment across desktop cover sizing and the fixed-height mobile crop. This is an artistic animation, not a physical simulation.

Rendering targets 30 frames per second, caps pixel ratio at 1.35 and drawing resolution at two million pixels. The scene renders only while its container intersects the viewport, the document is visible, reduced motion is disabled, and the visitor has not paused it. A bilingual pause/resume control freezes the current frame. Reduced motion and WebGL context loss reveal the original static backdrop; context restoration resumes the scene. Language changes cancel stale imports and release the previous scene's texture, geometry, material, renderer, animation frame, observers, and listeners.

The page uses semantic sections, native details/summary controls, visible focus states, and a skip link. Responsive styles cover mobile navigation, narrow screens, and short viewports, and have been checked in Chromium at desktop and mobile widths. Fonts load from Google Fonts with system fallbacks; font and mobile loading costs have not been profiled.

Build output is `dist/`, including the public résumé and compiled assets. `npm run smoke:dist` checks built JavaScript and CSS references, résumé presence, internal section anchors, and known external destinations. GitHub Pages runs this check after the production build. There are no server APIs, secrets, database connections, or environment variables. Email reveal assembles a client-side address and replaces the button with a focused mailto link. This is scraping friction only, not a privacy boundary.
